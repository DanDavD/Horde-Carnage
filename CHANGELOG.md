# Changelog

This file lists the notable changes to the project. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Versions follow [Semantic Versioning](https://semver.org/) while the game is a prototype (see [CONTRIBUTING](CONTRIBUTING.md#releases)).

## [Unreleased]

### Added
- **Build setup** (`CMakeLists.txt`, `CMakePresets.json`, `cmake/Dependencies.cmake`): a CMake project in C++20 that downloads raylib 5.5 and doctest 2.4.11 at configure time, pinned to those releases, so a fresh clone builds with one command. Presets for Debug and Release.
- **Strict warnings** (`cmake/Warnings.cmake`): `/W4 /WX /permissive-` on MSVC (and `-Wall -Wextra -Wpedantic -Werror` elsewhere) for the project's own targets only, so third-party code does not break the build.
- **Fixed-timestep loop** (`FixedTimestep.h`, `FixedTimestep.cpp`, `Game.cpp`): the game simulates at a fixed 60 Hz and renders once per frame, so gameplay does not depend on the monitor's refresh rate. Long frames are clamped to 0.25 s to avoid a spiral of catch-up steps. Covered by `FixedTimestepTests`.
- **Game window** (`Game.h`, `Game.cpp`, `main.cpp`): a 1280x720 window with vsync and a placeholder title screen whose bobbing title is driven by simulation time.
- **Tests and CI** (`tests/`, `.github/workflows/ci.yml`): doctest unit tests for the pure logic library `horde_core`, run by CTest, and a GitHub Actions workflow that builds Debug and Release and runs the tests on every push to `main` and every pull request.
- **Docs**: README, CONTRIBUTING, `docs/ARCHITECTURE.md`, `docs/ROADMAP.md` and a pull request template.
- **Vector math** (`Vec2.h`): a small 2D vector type for `horde_core`, so the pure logic and its tests do not depend on raylib. Covered by `Vec2Tests`.
- **Movement model** (`Movement.h`, `Movement.cpp`): a `Motion` component and a `StepMovement` function that accelerate toward a target velocity and brake at a stronger rate when the input is released or points against the velocity, so turning back takes 0.175 s instead of 0.2 s. Input is clamped to length 1, so a keyboard diagonal is not faster than a straight line and a half-pushed stick gives half speed. Covered by `MovementTests`, explained in `docs/MOVEMENT.md`.
- **Player in the arena** (`Player.h`, `Game.cpp`): the placeholder title screen is replaced by an arena with a floor grid and walls, and a player circle you can move. The player is drawn between the last two fixed steps, so movement is smooth above 60 Hz. `MotionAt` spawns a mover with both positions set, so its first frame is not drawn from the origin. Covered by `MovementTests`.
- **Arena walls** (`Arena.h`, `Arena.cpp`): `ConfineToArena` keeps a circle inside the arena and cancels only the velocity that points into a wall, so the player slides along walls instead of sticking. Covered by `ArenaTests`.
- **Keyboard and gamepad input** (`PlayerInput.cpp`, `AnalogInput.h`): WASD, the arrow keys, and the left stick and d-pad of the first gamepad. The stick goes through a radial deadzone that keeps diagonals and rescales from zero, so there is no jump in speed. Covered by `AnalogInputTests`.
- **Facing** (`Facing.cpp`, `Player.h`, `Game.cpp`): the player faces the way the input points and keeps that direction when it stops, shown by an eye on the player's edge. It follows the input, not the velocity, so the melee swing on day 4 goes where the player is pushing now. Covered by `FacingTests`.
- **Movement debug overlay** (`Game.cpp`): in Debug builds only, `F1` shows the input, speed, velocity, facing and position, and draws the velocity and facing as lines, so I can tune movement against numbers. Not unit tested; checked in a Debug build.
- **Follow camera** (`FollowCamera.h`, `FollowCamera.cpp`, `Game.cpp`): the arena grows to 2400x1600 and a camera follows the player with an exponential ease, looks ahead along the player's velocity, and stops 64 units past the walls so the walls stay visible. It is stepped in the fixed update and interpolated like the player. The Debug overlay shows its center. Covered by `FollowCameraTests`, explained in `docs/CAMERA.md`.
- **World** (`World.h`, `World.cpp`, `Game.cpp`): all the simulation state (arena, player, enemies, camera) moves into a plain `World` struct, and the whole fixed step into `StepWorld` in `horde_core`. `Game::Update` now only reads the input and calls it, so a full game step can run in a unit test without a window. Covered by `WorldTests`, including a check that the same inputs always give the same world.
- **Hairball enemy** (`Enemy.h`, `Chase.cpp`, `Game.cpp`): six hairballs spawn on a ring around the player and walk straight at it with the same movement and wall systems as the player, slower (160 against 300). They stop when they touch the player, so they do not shake on top of it. Drawn with tufts of hair and eyes that look at the player. The Debug overlay shows the enemy count. Covered by `ChaseTests` and `WorldTests`, explained in `docs/ENEMIES.md`.
- **Body collisions** (`Collision.cpp`, `World.cpp`, `Player.h`, `Enemy.h`): after everyone moves, overlapping bodies are pushed apart by weight (player 4, hairball 1) and lose the speed at which they were closing, like a perfectly inelastic collision. Four passes with the walls after each settle a crowd. Hairballs no longer pile into one behind a running player, one hairball barely slows the player (292 of 300) and a column of eight nearly stops them (51). Covered by `CollisionTests` and four new `WorldTests` cases, explained in `docs/COLLISIONS.md`.
- **Health and contact damage** (`Health.cpp`, `Collision.cpp`, `World.cpp`, `Game.cpp`): the player has 100 hit points and each hairball touch takes 10. After a hit the player is invulnerable for 0.8 s, so a crowd hurts like one hairball instead of six, and the player blinks to show it. A health bar in the top left corner turns pale during the window. Covered by `HealthTests`, a contact test in `CollisionTests` and three `WorldTests` cases, explained in `docs/HEALTH.md`.
- **Game over and restart** (`Session.cpp`, `PlayerInput.cpp`, `Game.cpp`): a small state machine (`Playing`, `GameOver`) around the world. At 0 hit points the world freezes and a game over screen shows the survival time. After 1 s, Enter, R, or A or Start on a gamepad start a fresh world. The frozen world is drawn without interpolation, so it does not shake. Covered by `SessionTests`, explained in `docs/GAME_FLOW.md`.
- **Mouse aim** (`Facing.cpp`, `PlayerCommands.h`, `Game.cpp`): the player faces the mouse cursor, independent of where it walks, like a twin-stick shooter. The app turns the hardware into a `PlayerCommands` struct, so the simulation never reads a device and tests drive it with plain values. A crosshair replaces the system cursor. Covered by `FacingTests` and `WorldTests`, explained in `docs/WEAPONS.md`.
- **Two guns** (`Weapon.cpp`, `Loadout.cpp`, `World.cpp`, `Game.cpp`): a semi-automatic pistol (one shot per click, at most 6 per second) and an automatic SMG (10 per second while held). A press up to 0.15 s early is kept and fired when the gun is ready. Q, 1, 2 or the mouse wheel switch guns, and a panel in the bottom right corner shows the gun in hand. A shot shows as a muzzle flash; bullets come next. Covered by `WeaponTests`, `LoadoutTests` and `WorldTests`, explained in `docs/WEAPONS.md`.
